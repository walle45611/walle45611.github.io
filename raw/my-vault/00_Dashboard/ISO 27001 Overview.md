## **ISO 27000 系列架構**

### **核心概述**

| **標準**        | **主要內容**                     |
| ------------- | ---------------------------- |
| **ISO 27000** | 定義資訊安全管理體系（ISMS）及基本名詞解釋。     |
| **ISO 27001** | 可作為驗證的標準，包含 ISMS 的要求事項。      |
| **ISO 27002** | 提供資訊安全控制項指南，輔助 ISO 27001 實施。 |

### **特定應用**

| **標準**        | **適用領域/功能**                  |
| ------------- | ---------------------------- |
| **ISO 27017** | 雲端服務相關控制項。                   |
| **ISO 27018** | 雲端隱私保護控制項。                   |
| **ISO 27701** | 隱私管理體系標準（PIMS），著重隱私保護驗證。     |
| **ISO 27110** | 提供 5 大核心結構指南：復原、識別、保護、發覺、回應。 |
| **ISO 27014** | 資訊安全治理（適用於政府機構）。             |
| **ISO 27011** | 電信產業資訊安全管理。                  |
| **ISO 27799** | 醫療健康資訊安全管理標準。                |

## **ISMS 的關鍵要素**

- 包括風險評估及處理要求，資訊安全管理其實就是風險管理，並且需要找到風險和 Cost 之間最優的一個平衡點。
- 何謂風險有的組織會依照 $Asset \times Threat \times Vulnerability$，或是等等公式，這個需要依照**程序書**所規定之內容，例如：機房設備-Server 可能會有資訊設備過熱弱點，威脅引發火災。
    
    ![[Assets/00_Dashboard/ISO 27001 Overview/ISO27001 資訊安全風險三要素示意圖.png|ISO27001 資訊安全風險三要素示意圖.png]]
    

1. **適用範圍（Scope）**
    - 遵循 P-D-C-A（Plan-Do-Check-Act）循環。
        
        ![[Assets/00_Dashboard/ISO 27001 Overview/ISO27001 PDCA範例圖.png]]
        
2. **風險管理方式**
    - **接受 (Accept)：** 接受風險可能性。
    - **降低 (Reduce)：** 採取措施減少風險。
    - **避免 (Avoid)：** 完全規避風險來源。
    - **轉移 (Transfer)：** 將風險轉移給第三方。
3. **ISMS 三大原則**
    - **機密性 (Confidentiality)：** 保護資訊不被未授權訪問。
    - **完整性 (Integrity)：** 確保資訊準確且不被未授權修改。
    - **可用性 (Availability)：** 保證資訊在需要時可用。
