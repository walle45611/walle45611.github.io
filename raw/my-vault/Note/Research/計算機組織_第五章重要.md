## 非 Pipeline vs Pipeline CPU Time 計算

- $S$ ：Pipeline 的 stage 數  
  例：5-stage pipeline → $S = 5$

- $T$ ：每個 stage 的 cycle time（時脈週期時間）  
  單位時間內一個 stage 執行一次

- $N$ ：要執行的指令數

| 項目 | 非 Pipeline | Pipeline |
|------|-------------|----------|
| **Cycle per instruction (CPI)** | $CPI = S$ | $CPI \approx 1$ (當 $N \to \infty$) |
| **總執行時間 (ExTime)** | $N \times S \times T$ | $[(S - 1) + N] \times T$ |
| **Speedup** | 1 (基準) | $\dfrac{N \times S}{(S - 1) + N}$，當 $N \to \infty$ → $\approx S$ |
| **Latency (單一指令完成時間)** | $S \times T$ | $S \times T$ (不變) |
| **Throughput (單位時間完成的指令數)** | $1 / (S \times T)$ | $1 / T$ (提升約 $S$ 倍) |

---

✅ **重點**：  
- **Latency** 不變 → 單一指令還是要走完 $S$ 階段。  
- **Throughput** 提升 → Pipeline 讓多條指令可以 overlapped 執行。  
- **理想 Speedup** 上限為 stage 數 $S$，但實際會因 hazard、register overhead、fill/drain 而低於 $S$。  
- pipelining 他不會減少 latency 但是可以增加指令的 throughput
- Pipeline 並不保證單一指令 latency 比 non-pipeline 短，它主要提升 throughput。
- Pipeline 的 clock cycle 是由 **最慢 stage 的延遲**決定。

## Pipeline Hazards

### 1. Structural Hazard

- 硬體資源不足，無法同時支援操作。
    
- 例：指令與資料共用 memory。
    

### 2. Data Hazard

- 資料尚未就緒，常見於 RAW。
    
- 例：
    
    ```
    lw  $t1, 0($t2)
    add $t3, $t1, $t4
    ```
    
- 指令距離足夠時，即使有依賴也不會 hazard。
- 一定要先 `sw` 再 `lw` 才不會產生 data hazard

### 3. Control Hazard

- 分支或跳躍造成 pipeline 取錯指令。
    
- 例：`beq`、`j`。
    

**解法**：reordering、NOP、stall。

## 資料依賴性
1. RAW (Read After Write)

	- **定義**：前一條指令寫，後一條讀，==**MIPS 才會有**==。 
	    
	- **範例**：
	    
	    ```
	    add $s0, $s1, $s2
	    sub $t1, $s0, $t2
	    ```
    

2. WAR (Write After Read)

	- **定義**：前一條讀，後一條寫，**==MIPS 沒有 hazard==**，但是其他 ISA 可能有。
	    
	- **範例**：
	    
	    ```
	    add $s0, $s1, $s2
	    sub $s1, $t0, $t2
	    ```
    

3. WAW (Write After Write)

	- **定義**：兩條都寫同一暫存器，**==MIPS 沒有 hazard==**，但是其他 ISA 可能有。
	    
	- **範例**：
	    
	    ```
	    lw  $s0, 12($s2)
	    sub $s0, $t0, $t2
	    ```
    

4. RAR (Read After Read)
	
	- **定義**：兩條都讀同一暫存器，無 hazard。
	    
	- **範例**：
		```
		add $t0, $s1, $s2
		sub $t1, $s1, $s3
		```

## 靜態和動態比較

| 類型                            | 解釋              | 優點             | 缺點                   | 適用場合              |
| ----------------------------- | --------------- | -------------- | -------------------- | ----------------- |
| **Static Branch Prediction**  | 永遠固定猜「會跳」或「不跳」  | 簡單、硬體成本低       | 準確率低，尤其在深流水線或迴圈中浪費效能 | 小型、低成本處理器         |
| **Dynamic Branch Prediction** | 依據執行時的歷史資訊來預測分支 | 預測準確率高，不需編譯器分析 | 硬體成本高（需要 BHT、BTB）    | 高效能處理器、深流水線、多發射架構 |

>如果考試沒有說 branch 相關指令在哪跳就是在 ID 跳
>先解決 Control hazard -> data hazard
>store word 後面不會有 data hazard
