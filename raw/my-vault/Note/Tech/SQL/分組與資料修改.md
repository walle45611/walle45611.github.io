# 分組與資料修改

## [#182 Duplicate Emails](https://leetcode.com/problems/duplicate-emails/)

這題要列出重複的 email。你提出的查詢：

```sql
SELECT email
FROM Person
GROUP BY email
HAVING COUNT(email) > 1;
```

`GROUP BY` 將相同 email 分組，`HAVING` 再篩選筆數大於 1 的群組。分組不代表輸出會排序；要排序需另用 `ORDER BY`。

## [#511 Game Play Analysis I](https://leetcode.com/problems/game-play-analysis-i/)

每個玩家的首次登入日期也可以直接用聚合表示：

```sql
SELECT player_id, MIN(event_date) AS first_login
FROM Activity
GROUP BY player_id;
```

這是 #511 的 self join 寫法的另一種解法，見 [[Note/Tech/SQL/JOIN 與反連接]]。

對話中比較過 `GROUP BY + MIN()` 和 self join 的單次 LeetCode runtime。執行計畫、索引和測量波動都會影響時間；要比較時查看 `EXPLAIN` / `EXPLAIN ANALYZE` 並多次測量，不要只依一次時間下結論。

## [#196 Delete Duplicate Emails](https://leetcode.com/problems/delete-duplicate-emails/)

這題要實際刪除重複列，保留每個 email 最小的 `id`。對話中的 MySQL self join 範例：

```sql
DELETE p1
FROM Person p1
JOIN Person p2
    ON p1.email = p2.email
   AND p1.id > p2.id;
```

提交 `DELETE` 即可。LeetCode 執行後會顯示資料表，不用再加 `SELECT`。

## 易錯點

- #182 是查出重複值，用 `SELECT`、`GROUP BY`、`HAVING`；#196 是刪掉多餘列，用 `DELETE`。先確認題目要求「找出」還是「刪除」。
- `WHERE` 篩選分組前的列，`HAVING` 篩選分組後的統計結果。
- `GROUP BY` 是分組，不是排序；需要排序時寫 `ORDER BY`。
