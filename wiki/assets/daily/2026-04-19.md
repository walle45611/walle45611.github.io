- 主題名稱：Harness Engineering：有時候語言模型不是不夠聰明，只是沒有人類好好引導
- source link: https://www.youtube.com/watch?v=R6fZR_9kmIw&t=5012s
- 1 句話核心概念：AI agent 的實際表現高度取決於 harness 設計，也就是規則、工具與回饋流程如何把模型導向可用結果。
- 3-5 個重點
  1. Agent 能力是 `LLM + Harness` 的乘積，規則檔與工作流設計會直接影響完成率。
  2. 工具決定能力邊界，對模型友善的工具應偏向可摘要、可結構化、低噪音。
  3. generator/evaluator 類回饋迴圈能穩定提升多步任務品質。
  4. 自然語言 feedback 應具體、可執行，避免情緒化指責。
  5. 長期運作 agent 需要記憶整理機制，避免上下文膨脹退化。

- 主題名稱：解剖小龍蝦 — 以 OpenClaw 為例介紹 AI Agent 的運作原理
- source link: https://www.youtube.com/watch?v=2rcJdFuNbZQ&t=1s
- 1 句話核心概念：OpenClaw 展示了 agent 並不是模型本身，而是把 system prompt、工具、記憶與排程組成可持續運作框架的執行層。
- 3-5 個重點
  1. 模型的「人格、記憶、目標」多半來自注入的規則與本地檔案，而非模型天生具備。
  2. 高權限工具同時帶來能力與風險，不能只靠模型服從做安全控制。
  3. context engineering 包含按需載入 skill、子代理分工、記憶檢索與上下文壓縮。
  4. 關鍵規則若只存在聊天歷史，可能在 compact 後消失，應寫入長期記憶檔。
  5. 生產環境應採隔離機器、獨立帳號與最小權限原則。

- 主題名稱：MicroK8s 完整部署指南：從安裝到生產級應用
- source link: https://blog.walle4561.com/20250808/ecf5/#more
- 1 句話核心概念：MicroK8s 可以進入 production，但前提是先補齊 HA、網路元件、權限治理與 GitOps 交付鏈。
- 3-5 個重點
  1. 生產基線需要 DNS、儲存、Ingress、MetalLB、Metrics 等核心插件。
  2. Helm、Argo CD、Sealed Secrets、Image Updater 可組成可維護的 GitOps 交付流程。
  3. 權限、網路與 registry credentials 應在初始設計階段制度化，不要後補。
  4. `hostpath-storage`、節點治理與防火牆開孔等細節會直接影響可用性。
  5. MicroK8s 是否適合 production，取決於規模、HA 與運維能力，不是單靠官方標籤。
