### Kubernetes / Linux 系統複習

- Kubernetes CRI: https://kubernetes.io/docs/concepts/containers/cri/
- Kubernetes network plugins / CNI: https://kubernetes.io/docs/concepts/extend-kubernetes/compute-storage-net/network-plugins/
- Kubernetes containers: https://kubernetes.io/docs/concepts/containers/
- Multi-container Pods: https://kubernetes.io/blog/2025/04/22/multi-container-pods-overview/
- 今日複習重點：
  - CRI 是 kubelet 與 container runtime 之間的 gRPC 介面；containerd / CRI-O 等 runtime 透過 CRI 與 Kubernetes 整合。Docker Engine 本身不直接實作 CRI，舊的 dockershim 已自 Kubernetes v1.24 移除。
  - CNI 是 cluster networking 的 plugin 規格；Kubernetes 需要相容的 CNI plugin 實作 Pod networking。今天也複習 Calico、Cilium、Flannel、NetworkPolicy 與 eBPF 的差異方向。
  - Pod 是 Kubernetes 的共同排程單位；同 Pod containers 會 co-locate / co-schedule，適合緊密耦合的 init / sidecar / helper 模式，但若兩個服務需要獨立擴縮、排程或故障隔離，通常不應硬塞進同一 Pod。
  - 今日亦複習 `runc` / OCI、container runtime stack、Pod anatomy，以及 init / sidecar 等 supporting container 的角色。

### PXE / dnsmasq / 面試實作準備

- 今日閱讀與討論的實作方向包含 PXE network boot、dnsmasq、OrbStack VM lab 與 Linux `ip` 指令。
- 關鍵區分：PXE 是網路開機機制，不是 Proxmox VE；典型流程會涉及 DHCP 提供 boot 資訊，再從 TFTP / HTTP 等來源取得 bootloader、kernel 或 installer。
- `dnsmasq` 是輕量的 DNS forwarder / DHCP / TFTP 工具，常被用來快速搭建小型 PXE lab；它與 BIND9 的定位不同，BIND9 更偏完整 DNS authoritative / recursive server。
- 面試準備脈絡則集中在系統與網路管理實務：Git / rebase、Linux、nftables、PAM、OSPF、STP、VLAN、DNS、Mail/DNS、HPC、server hardware、Ansible 與 Kubernetes。
