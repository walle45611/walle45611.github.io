- Understanding Linux User Namespaces
  - source: `raw/web-clipper/Michael Kerrisk  Understanding Linux user namespaces.md`
  - source link: https://www.youtube.com/watch?v=XgThPoL9mPE
  - 1 句話核心概念：Linux user namespace 可以讓程序在 namespace 內呈現 UID 0 與 capabilities，但實際權限仍受管理目標資源的 user namespace 與 UID/GID 映射邊界限制。
  - 3 到 5 個重點：
    - UTS、mount、network 等 namespace 分別隔離不同系統資源；`/proc/<pid>/ns/` 可用來辨識程序是否位於相同 namespace instance。
    - capabilities 將傳統 root 權限拆成多種權能；演講中提到的 capabilities 數量屬 2023 年當時資訊，不應視為永久規格。
    - `/proc/<pid>/uid_map` 與 `gid_map` 可將 namespace 內 UID/GID 映射到外部身分，例如內部 UID 0 對應外部 UID 1000。
    - 在新 user namespace 內具有 `CAP_NET_ADMIN` 或其他 capability，不代表能管理初始 namespace 的主機資源；權限檢查取決於資源由哪個 user namespace 管理。
    - user namespace 可用於無特權容器與 sandbox，但通常需搭配其他 namespace、seccomp 等隔離機制，不能單獨視為完整容器或安全政策。

## 知識串聯

這篇補強了既有的 container networking 筆記：network namespace 回答「網路資源如何被隔離」，user namespace 則進一步回答「誰有資格建立、管理與操作這些隔離資源」。在理解容器安全時，UID 0、capability 與 host root 不能直接畫上等號，必須同時檢查 UID/GID mapping、user namespace 階層與目標資源的 ownership boundary。
