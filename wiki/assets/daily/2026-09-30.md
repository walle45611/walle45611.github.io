- Linux 記憶體管理入門
  - source: `raw/web-clipper/Introduction to Memory Management in Linux.md`
  - source link: https://www.youtube.com/watch?v=7aONIVSXiJ8
  - 1 句話核心概念：程式看到的虛擬位址由 MMU、TLB 與 page tables 映射到實體 page frame，因此連續的虛擬位址不代表背後實體記憶體也連續。
  - 5 個重點：
    - 虛擬記憶體讓不同 process 擁有各自的位址視圖與存取權限；TLB 只快取部分位址翻譯，不等於完整映射表。
    - 講者用 32-bit、3 GiB user／1 GiB kernel 作示例，區分 kernel logical 與 kernel virtual 位址；`kmalloc()` 與 `vmalloc()` 對實體連續性的需求不同，但這些版面配置與 page 大小不能推廣成所有平台固定規則。
    - 相同虛擬位址可在不同 process 指向不同 frame；不同虛擬位址也可映射同一 frame 形成共享記憶體，而同步與互斥仍需另外處理。
    - 虛擬位址範圍與實體 backing 可以延後綁定；首次存取可能觸發 fault，再由核心建立 backing，因此 first-touch latency 對量測與時間敏感工作有影響。
    - page tables 保存比 TLB 更完整的映射資訊；swap-in 後資料可能回到不同 frame 而維持原虛擬位址。使用者空間常見介面包括 `mmap()`、`brk()`／`sbrk()` 與 allocator／stack growth，但實際行為受 allocator、架構與設定影響。

## 知識串聯

今天的內容可以用「位址抽象層」串起來：process 使用虛擬位址，CPU 透過 MMU／TLB／page tables 找到實體記憶體，而 DMA 又有自己的裝置可見位址語意。排錯時應先分清 virtual address、CPU physical address、DMA address，再判斷 fault、swap、allocation 或 I/O 問題所在層次。這篇來源是 2017 年講座，32-bit 分界、4 KiB page、highmem 與特定 TLB refill 描述需保留年代與架構限制。
