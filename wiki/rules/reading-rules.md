# 閱讀回顧與每日整理

回顧是在對話中整理指定時段；daily 是寫入每日紀錄，只有使用者要求或排程明確指定時才建立。主題分析用 query，兼含時間條件時先找時段資料再分析。

## 共通選材

- 使用 Asia/Taipei 當下日期換算相對日期，標明實際範圍。
- 直接依 `wiki/summaries/` 各頁的 `ingested_at` 篩選；這是收錄日，不是來源發布日或剪藏建立日。缺少此欄位時標記資料不足，不由檔案修改時間推定。
- 實際讀取納入的摘要或 daily，不只列目錄與檔名。只根據已歸檔內容整理，不為回顧或重建 daily 全量重掃 raw。
- 來源優先用摘要的 source link，沒有才用 source；兩者皆無則省略，不構造網址或補外部資訊。

## 閱讀回顧

1. 單日或 4 天以內：依摘要的收錄日期篩選，逐篇讀摘要。
2. 超過 4 天：優先逐日讀取現存 daily；超過保留期限或缺少 daily 時，依摘要的收錄日期篩選並讀取內容，明示使用的資料與缺漏，不補造內容；概念頁僅輔助理解。
3. 回覆依序包含日期範圍、總覽、逐篇摘要與可選的知識串聯；每篇交代主題、1 句核心概念、3–5 個重點與來源。
4. 沒有資料時如實說明，區分紀錄缺漏與確定沒有收錄。日誌依任務入口的共通規則。

## 建立或更新 Daily

1. 依目標日的 `ingested_at` 找摘要並逐篇讀取；同一摘要不重複收錄。
2. 寫入 `wiki/daily/YYYY-MM-DD.md`，同日只更新同一份檔案。
3. 依下列保留期限清理過期 daily ，更新每日整理導航，再追加日誌，記錄 basis、輸出路徑、摘要與清理數量。
4. 沒有摘要時記錄 0 篇，basis 填 `[]`，記錄檢查摘要收錄日期的範圍。日期不明、來源不足或寫入失敗時如實回報；回覆反映實際內容與結果。

## 保留期限

- 只保留最近 30 個日曆日，包含 Asia/Taipei 的今天；下限為今天減 29 天，以檔名日期判斷，不以檔案修改時間或最近 30 份判斷。
- 每次建立／更新 daily 或執行 daily 維護時，刪除早於下限的 daily，重建 `wiki/archives/daily-records.md`。不補建缺少日期；超過期限的日期不再建立 daily。
- 清理僅限 daily，原始來源、摘要與概念保留；日誌依任務入口另保留最近 30 天；舊日誌的檔案引用代表當時紀錄，不保證 daily 永久存在。

Daily 使用以下骨架，來源欄位僅保留已知資訊，知識串聯沒有明顯關聯時省略：

```md
# Daily Digest <YYYY-MM-DD>

- date: <YYYY-MM-DD>
- timezone: Asia/Taipei
- generated_at: <實際產生日期>
- basis: <已讀摘要的內部連結>

## Summary

共整理 <N> 篇內容。

### <主題>

- source: <摘要記錄的原始路徑>
- source link: <已知外部網址>
- 核心概念：<一句話>
- 重點：<3–5 個重點>

## 知識串聯

<當日內容的共同觀察>
```
