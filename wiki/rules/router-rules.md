# 任務入口

先讀本檔，再依任務讀下表對應規則；不必每次讀完全部規則。任務包含多種工作時，搭配相關規則。

| 任務 | 規則 |
| --- | --- |
| 整理、摘要、歸檔新來源 | [ingest](ingest-rules.md) |
| 主題查詢、比較、統整 | [query](query-rules.md) |
| 清理、健康檢查、lint、規則維護 | [lint](lint-rules.md) |
| 閱讀回顧、建立或更新每日整理 | [reading](reading-rules.md) |

## 共通原則

- 來源與寫入邊界依根目錄 `AGENTS.md`；優先整合既有頁面，避免重複摘要與過度拆頁。
- 只根據實際讀取的資料整理，保留出處、時間、版本、條件與不確定性；跨來源結論放在概念頁，分歧需標明。
- 預設以繁體中文自然回覆；格式依使用者要求，寫入 wiki 使用 Markdown。說明實際結果與限制，不用篇名或連結清單取代必要分析。

## 操作日誌

- 歸檔、daily、wiki 回寫、lint 修正與規則維護完成後，必須追加 `wiki/log.md`；純人工查詢／回顧只有使用者要求留痕時才記錄。
- Worker、webhook、agent 或排程自動觸發的系統任務必須記錄；一般人工對話不因使用 AI 助理就算系統任務。
- 日誌只保留最近 30 個日曆日（包含 Asia/Taipei 今天，下限為今天減 29 天）；每次追加或維護時按條目標題日期清除過期紀錄，不另搬入 archives。保留期限內的既有內容不改寫。
- 先完成主要工作，再追加到檔案尾端，不插入中間或改寫歷史；只記實際讀取、變更、結果與驗證。寫入失敗須回報「log 尚未寫入」及原因。

```md
## [YYYY-MM-DD] <任務類型> | <主題>

- checked: <來源、讀取頁面或檢查範圍>
- updated: <實際變更或結果；新增／修正可另列 created／fixed>
- verified: <已執行的驗證>
- gaps: <來源邊界、未解問題或失敗原因>
```
