## Summary

這篇文章回顧 Notion、HackMD、Jekyll 與 Hexo 的取捨，並記錄使用 Hexo CLI 初始化 Blog、設定 `_config.yml`、套用 NexT、加入 robots.txt、啟動本機伺服器與部署到 GitHub Pages 的流程。

## Key Points

- 原文選擇 Hexo 的理由是寫作流程較簡潔、與 NPM 生態整合，以及比 Jekyll 更容易開始。
- `source/_posts`、`_config.yml` 與 theme 設定是 Hexo 專案的主要維護面。
- 文章同時記錄 GitHub Pages、`hexo deploy` 與 GitHub Actions 兩種部署方向。
- 本次搬移保留這段歷史；後續知識維護不再以 Hexo 專案作為主要工作面。
